# Changelog - 2026-01-28

## Enhancements to reopen-accessreview.ps1

### New Features

#### 1. Script Metadata Display

- Script now displays its name and Last Modified date from the header at startup
- Metadata is also saved to output logs for troubleshooting and audit purposes

#### 2. Output Logs (Renamed from Debug Logs)

- **Always generated by default** for both successful and failed operations
- Renamed from "debug" to "output" logs throughout the script
- Output logs now include:
  - `ScriptName`: Name of the script
  - `ScriptLastModified`: Timestamp from header
  - `Success`: Boolean indicating success/failure
  - `ProblematicSettingsDetected`: Array of problematic settings found
  - `OriginalDefinition`: Source access review definition
  - `AttemptedBody`: The payload sent to Graph API
  - `ErrorMessage` & `ErrorDetails`: (only for failures)

#### 3. New Parameters

##### `-SuppressOutputLogs`

- Suppresses automatic output log generation for successful operations
- If an error occurs when logs are suppressed, the user is prompted to generate the log
- Default: Output logs are generated (not suppressed)

##### `-DisplayBody`

- Shows the JSON payload that will be sent to Microsoft Graph API
- Useful for debugging and understanding what data is being sent
- Default: Body is not displayed

#### 4. Problematic Settings Detection

The script now automatically detects problematic settings that were removed in the simplified implementation:

- `recommendationLookBackDuration` - TimeSpan objects cause serialization issues
- `recommendationInsightSettings` - Complex objects may cause validation errors
- `accessRecommendationsEnabled` - Not supported in v1.0 API

When detected:

- **Warning displayed** during execution with details
- **Logged to output file** for future reference
- Settings are **NOT copied** to the new definition

#### 5. Enhanced Error Handling

- When logs are suppressed and an error occurs, user is prompted to generate output logs
- 5-second auto-accept timeout for user convenience
- All errors now generate comprehensive output logs with full context

### Updated Pre-Commit Hook

- Added clarifying comment in `pre-commit-cleanup-gitkeep.sh`
- Hook now explicitly documents that it handles both comment-only and code changes
- Ensures Last Modified timestamps are always current

### Output Log Naming Convention

Changed from: `debug-accessreview-{DefinitionId}-{timestamp}.json`
To: `output-accessreview-{DefinitionId}-{timestamp}.json`

### Benefits

1. **Better Audit Trail**: Every operation is logged by default with full context
2. **Proactive Warnings**: Users are informed about problematic settings before they cause issues
3. **Flexible Output**: Users can suppress logs for clean output or enable detailed payload display
4. **Improved Troubleshooting**: Output logs include script version info and problematic settings
5. **User-Friendly**: Auto-save behavior reduces friction, prompts only when needed

### Breaking Changes

None - all new features are additive with sensible defaults.

### Backward Compatibility

✅ Existing scripts and workflows will continue to work
✅ New output logs are additive and don't replace existing functionality
✅ Old debug files (if any exist) are not affected
