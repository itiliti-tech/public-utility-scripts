# Access Review Script Fixes - 2026-01-28

## Problem Summary

The script was failing with HTTP 400 Bad Request errors when trying to create one-time access review definitions cloned from existing recurring reviews.

## Root Causes Identified

### 1. **Incorrect Settings Structure** ❌ → ✅

**Before:**

```powershell
$body = @{
    # ... other properties ...
    settings                = $settingsHt
    recurrence              = buildOneTimeRecurrence $StartDate
    instanceDurationInDays  = $InstanceDurationInDays
}
```

**After (Correct per Microsoft Documentation):**

```powershell
# recurrence and instanceDurationInDays go INSIDE settings
$body = @{
    # ... other properties ...
    settings = @{
        instanceDurationInDays = 7
        recurrence = @{
            pattern = @{ type = "weekly"; interval = 1 }
            range   = @{ type = "numbered"; startDate = "2026-01-28"; numberOfOccurrences = 1 }
        }
        # ... other settings properties ...
    }
}
```

**Microsoft Documentation Reference:** According to the [accessReviewScheduleSettings](https://learn.microsoft.com/en-us/graph/api/resources/accessreviewschedulesettings?view=graph-rest-1.0) resource type, both `recurrence` and `instanceDurationInDays` are properties of the settings object, NOT the root definition object.

### 2. **Complex Scope Handling** 🔧

The original script assumed simple `accessReviewQueryScope` scopes, but the actual definitions used `principalResourceMembershipsScope` with both `principalScopes` and `resourceScopes` arrays.

**Scope Structure Found:**

```json
{
  "@odata.type": "#microsoft.graph.principalResourceMembershipsScope",
  "principalScopes": [
    {
      "@odata.type": "#microsoft.graph.accessReviewQueryScope",
      "query": "/v1.0/users?$filter=userType eq 'Guest'",
      "queryType": "MicrosoftGraph"
    }
  ],
  "resourceScopes": [
    {
      "@odata.type": "#microsoft.graph.accessReviewQueryScope",
      "query": "/v1.0/groups/{id}/transitiveMembers/microsoft.graph.user/?$count=true&$filter=(userType eq 'Guest')",
      "queryType": "MicrosoftGraph"
    },
    {
      "@odata.type": "#microsoft.graph.accessReviewQueryScope",
      "query": "/v1.0/teams/{id}/channels?$filter=membershipType eq 'shared'",
      "queryType": "MicrosoftGraph"
    }
  ]
}
```

**Fix:** Updated script to preserve the entire scope structure using `unwrapGraphObject` instead of trying to extract a single query.

### 3. **Missing Description Handling** ✅

The script now ensures both `descriptionForAdmins` and `descriptionForReviewers` are never null or empty:

- If `descriptionForAdmins` is empty, uses: "Cloned from {DefinitionId} on {date}"
- If `descriptionForReviewers` is empty, uses: "Please review your access."

## Code Changes

### 1. New Helper Function: `buildSettingsObject`

```powershell
function buildSettingsObject {
    param(
        [object]$oldSettings,
        [datetime]$StartDate,
        [int]$InstanceDurationInDays
    )

    $settingsHt = @{}

    # Copy safe subset of settings from old definition
    foreach ($k in @('mailNotificationsEnabled', 'reminderNotificationsEnabled',
                     'justificationRequiredOnApproval', 'defaultDecisionEnabled',
                     'defaultDecision', 'recommendationsEnabled',
                     'autoApplyDecisionsEnabled', 'accessRecommendationsEnabled',
                     'decisionHistoriesForReviewersEnabled')) {
        if ($oldSettings -and $oldSettings.PSObject.Properties[$k]) {
            $settingsHt[$k] = $oldSettings.$k
        }
    }

    # Set the instance duration and recurrence at the settings level
    $settingsHt['instanceDurationInDays'] = $InstanceDurationInDays
    $settingsHt['recurrence'] = buildOneTimeRecurrence $StartDate

    return $settingsHt
}
```

### 2. Updated Scope Handling

```powershell
# Unwrap and properly structure the scope based on its type
$scopeHt = unwrapGraphObject $scopeData

# Ensure @odata.type is present (required for principalResourceMembershipsScope)
if (-not $scopeHt.'@odata.type') {
    if ($scopeHt.ContainsKey('principalScopes') -or $scopeHt.ContainsKey('resourceScopes')) {
        $scopeHt.'@odata.type' = '#microsoft.graph.principalResourceMembershipsScope'
    } elseif ($scopeHt.ContainsKey('query')) {
        $scopeHt.'@odata.type' = '#microsoft.graph.accessReviewQueryScope'
    }
}
```

These functions properly normalize `principalScopes` and `resourceScopes` arrays with correct @odata.type values.

## Key Learnings

1. **Always check Microsoft Graph API documentation** - The structure of nested objects matters greatly
2. **Settings vs Root Properties** - `recurrence` and `instanceDurationInDays` belong inside `settings`, not at the root
3. **Scope Complexity** - Access reviews can have simple or complex scopes; don't assume structure
4. **@odata.type is Critical** - Required for `principalResourceMembershipsScope` and strongly recommended for all scope types
5. **PowerShell SDK Object Unwrapping** - The Graph PowerShell SDK wraps objects; use `AdditionalProperties` and custom unwrapping functions
